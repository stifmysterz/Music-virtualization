## 二、需要你亲自完成的验收

这三项无法自动化，必须人工操作。

### ✅ 前置：先安装

运行 `dist\SUB REMIX Setup 1.0.0.exe`。

- 安装包**未做代码签名**，Windows SmartScreen 会拦一下 →
  点「更多信息」→「仍要运行」即可。这是预期行为，不是软件有问题。
- 图标是 Electron 默认图标（紫色原子），按你的决定暂缓，随时可换。

### ⚠️ 三处与浏览器版不同的行为，先看一眼免得误判成 bug

**1. 录制中关窗口会弹确认框（新增的保护）**

浏览器版里，录制到一半关掉标签页或按 Ctrl+R，录制会**静默丢失**，不给任何提示。
桌面版加了保护：录制中关窗口会弹出「Recording in progress… Close Anyway?」。
这是新行为，浏览器里没有。

**2. Ctrl+R / Ctrl+Shift+R / Ctrl+Shift+I 现在完全没反应**

这是刻意的。Electron 默认菜单的快捷键原本是绑着的，录制中误按 Ctrl+R
会重载页面、静默毁掉整条录音，并留下一个从未正常关闭的截断文件。
现在整个菜单和快捷键都移除了。

**副作用：Ctrl+Shift+I 开发者工具也没了。** 如果你排查问题时习惯用它，现在得走别的路
（告诉我，我可以加回一个只在需要时启用的入口）。

**3. 取消保存对话框会导致内存缓存 ⚠️**

点录制后会弹出系统保存对话框。**如果你按 Esc 或点取消，程序不会停止录制，
而是静默改用内存缓存**，约 225 MB/分钟。这不是打包引入的，浏览器版本来就这样
（`61.html:19945`）。录长片时留意别误按取消。

### 验收项 2 · 长录制内存监控 ⭐ 最重要的一项

**目的：** 确认录制时内存不会随时长增长。这是 spec 第 5.2 节标记的最大风险点。

**为什么重要：** 如果代码没走磁盘流式写入而是在内存里堆数据，按 30Mbps 算，
录 5 分钟约吃 1.1GB，10 分钟约 2.2GB，长录制会卡死或崩溃。
自动化只能证明 API 可用，**只有真实录制才能证明内存真的是平的**。

**步骤：**

1. 打开软件，导入一首歌
2. 开始录制，录满 5 分钟
3. 全程打开任务管理器（Ctrl+Shift+Esc），盯住 **SUB REMIX** 进程的内存占用
4. 每分钟记一次

**记录：**

| 时间 | 内存占用 |
|---|---|
| 0 分钟（刚开录） | |
| 1 分钟 | |
| 2 分钟 | |
| 3 分钟 | |
| 4 分钟 | |
| 5 分钟 | |

**通过标准：** 内存基本平稳，不随时长线性增长。

**不通过的信号：** 若 5 分钟时比 1 分钟时增长**超过 500MB**，说明落盘路径没生效
